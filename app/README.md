# 选股助手 App

**App 是引擎，知识库是内容。** 这个 App 不含任何行情数据、不含任何大V内容，
它做的是：载入知识库 → 让 AI 带着工具去查证 → 结合你的真实持仓给分析。

---

## 四个功能

### 1. 设置 → 模型（用户自带 LLM）

自己填 `Base URL` + `API Key` + 模型名，可配多个并指定默认。
内置 DeepSeek / 通义 / Kimi / 智谱 / OpenAI / Ollama / vLLM 的预设。

- **请求从本机直发你选的服务**，我们不中转、不代管 key
- 可标记「支持识图」（截图导入持仓需要）与「支持 JSON 输出」（结构化抽取需要）
- 有「测试连接」和「拉取模型列表」

> **密钥安全**：存在本机 IndexedDB，**未加密**。这是纯前端应用的固有限制。
> 请勿在公用设备使用，建议为本用途单独申请一个限额 Key。

### 2. 全局记忆（截图 → 持仓 → 画像）

上传券商持仓截图，识图模型读出持仓与盈亏，写入个人档案，并据此推测偏好。

**两个刻意的摩擦设计**（都是为了防止污染后续所有分析）：

1. **识别结果默认 `confirmed=false`**，必须逐条核对勾选才计入。
   券商截图数字密集，识图模型错一位数，之后所有的"贴心建议"都会是错的，
   而且极难事后发现。
2. **每条画像结论都能展开看到依据，且可单独删除**。
   个人画像不是黑盒——用户要能看到「为什么 AI 认为我偏好短线」。
   持仓分布还有一套**不依赖模型**的本地统计（`sectorDistribution`），
   可以和模型输出交叉验证。

> 一个刻意的保守设计：**持有某股票不等于看好该行业**（可能是套牢）。
> 提示词里明确要求模型在标的明显亏损时谨慎表述。

### 3. 多会话 + 记忆开关

每个会话独立决定：

| 开关 | 语义 |
|---|---|
| **共享记忆** | AI 知道你的持仓与偏好，回答针对你的仓位 |
| **隔离记忆** | AI 看不到任何个人信息，只做纯粹的标的分析 |

关掉时提示词里会**明确写「用户已关闭全局记忆」**，而不是仅仅不喂数据——
否则模型会自己去猜、去假设用户持有。

会话还可以：
- 选择**多个军师**（多知识库并列呈现不同来源的观点）
- 设定**聚焦标的**，让检索优先命中它

### 4. 知识库载入（换军师）

载入 `.stkb` 文件即可更换"军师"。格式规范见
[../docs/kb-format.md](../docs/kb-format.md)。

App 会展示每个知识库的：观点数、标的数、体积、**各周期的命中率与
Wilson 置信区间下界**、作者画像与方法论。

> 如果知识库是**词表规则**抽取的（`extractor.mode === 'rule'`），
> App 会显示醒目警告，并且**提示词里也会告诉模型**
> 「该库方向判断可信度低，回答时必须告知用户」。
> 实测证实了这一点：规则抽取在口语化、正话反说的内容上会判出**相反**的方向。

## AI 会自己调用工具

不是"我们把检索结果塞给它"，而是**它自己决定查什么、查几次**。
每次调用了什么、查到了几条，都显示在对话里。

> **这是判断答案可信度的唯一依据。** 模型编造时的典型特征就是：一个工具都没调。

| 工具 | 作用 | 数据源 | 需要 key |
|---|---|---|---|
| `kb_search` | 检索知识库历史观点，**附带每条观点事后的真实收益** | 本地 | 否 |
| `kb_performance` | 查命中率（含样本量、Wilson 区间、符号检验 p 值） | 本地 | 否 |
| `kb_coverage` | 列出知识库覆盖了哪些标的、大V画像 | 本地 | 否 |
| `stock_quote` | 实时股价、涨跌幅、成交额、PE/PB、市值 | 腾讯财经 | 否 |
| `fund_holdings` | 基金前十大重仓股 | 天天基金 | 否 |
| `web_search` | 联网搜新闻、政策、公告 | Tavily / Brave / Serper / 自建 | **是** |
| `fetch_page` | 读取指定网页正文 | 任意 URL | 否 |

### 三个关键设计

1. **有轮数上限**（默认 6）。没有上限的 Agent 会在模型犯轴时无限调用工具烧 token，
   而用户只能看着进度条转。达到上限会强制收尾**并明确告知用户"这条回答不完整"**。

2. **工具失败不是错误**。失败结果照样回给模型，并在提示里明确
   「如实告知用户拿不到，**绝对不要用记忆里的价格冒充**」。
   断网时模型仍能基于知识库回答。

3. **工具轮的"思考文本"单独存放**。模型常先说「让我查一下最新价格」再发起调用，
   这段文字不是答案，混进正文会让人误以为那就是回答。

## ⚠️ CORS：现在能用什么、不能用什么

这是当前最大的现实约束。

| 环境 | 行为 |
|---|---|
| **浏览器开发模式**（现在） | 普通 `fetch`。腾讯/东财行情、多数搜索 API **会被跨域拦截** |
| **Capacitor 打包后** | 走原生 HTTP，**没有 CORS 限制**，全部工具可用 |

代码已经为这个切换留好了挂载点（`src/lib/http.ts` 的 `registerNativeHttp`），
打包后在 `main.ts` 里注入 Capacitor 的 `CapacitorHttp` 即可，**业务代码一行不用改**。

被跨域拦截时，工具会返回**明确的原因**（「跨域(CORS)或网络被拦…打包成 App 后
走原生 HTTP 就没有这个限制」），而不是静默返回空结果让模型瞎编。

**所以现在浏览器里能完整验证的是**：知识库检索、命中率统计、提示词组装、
会话与记忆的完整交互。行情与联网搜索要等打包后才能真正生效。

## 目录结构

```
app/
  src/
    types.ts              领域模型（Provider / KnowledgeBase / Memory / Session / ToolConfig）
    lib/
      db.ts               IndexedDB 封装（自己写的一百行，不引依赖）
      http.ts             HTTP 抽象层（CORS 与原生 HTTP 的切换点）
      stats.ts            Wilson 区间与符号检验（与 Python 侧同一套算法）
      fmt.ts              格式化 + 极简 Markdown 渲染
    services/
      llm.ts              OpenAI 兼容客户端（流式 + function calling）
      kb.ts               .stkb 解析 + 标的名匹配
      prompt.ts           ★ 提示词组装：把大V画像、历史观点、真实收益、
                            用户持仓拼成有据可查的上下文
      memory.ts           截图识图 + 画像推断
      agent.ts            ★ Agent 循环：工具调用、轮数控制、失败降级
      tools/
        types.ts          工具接口
        index.ts          注册表 + 可用性判定
        kb.ts             知识库工具
        market.ts         行情与基金持仓
        web.ts            联网搜索与读页
    stores/               providers / knowledge / memory / sessions / tools
    views/                4 个页面
  tests/smoke.ts          核心逻辑冒烟测试（Node 环境，不需要浏览器）
```

## 打包成 App（下一步）

```powershell
pnpm add -D @capacitor/cli @capacitor/core
npx cap init
npx cap add android
pnpm build && npx cap sync
```

打包后要做两件事：
1. 在 `main.ts` 里注入原生 HTTP 实现（解决 CORS）——**这是解锁全部工具的关键**
2. 用 hash 路由（已配置好）——`file://` 下 history 模式会 404

**体积预期**：当前 gzip 后约 **94 KB**。因为知识库在外部，
App 体积不随知识库数量增长——这正是"引擎与内容分离"的直接收益。
