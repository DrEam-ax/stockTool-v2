# 知识库产物说明

格式规范见 [../../docs/kb-format.md](../../docs/kb-format.md)。

**契约：一个 `.stkb` = 一位军师。** 要组建"军师团"就导出多个、在 App 里一起载入。

---

## 仓库里有的文件

| 文件 | 体积 | 内容策略 | 用途 |
|---|---|---|---|
| `demo_junshi_1/2/3.stkb` | 各 ~6 KB | `evidence_only` | 3 位**合成**测试大V，用于试"多军师"与多库对比 |
| **`demo_junshi_persona.stkb`** | ~9 KB | `evidence_only` | **带完整决策框架**的合成军师。测试用它当 fixture，也用来试「军师 / 检验」模式 |

这几份都是**虚构人物、虚构观点**，可以随便传阅、改、拿去做测试。

### 为什么仓库里没有"真实"知识库

真实语料与由它派生的知识库**不在这个仓库**，因为：

1. 它含大量他人的原始发言（`full_text` 策略下是逐字原文）；
2. 更重要的，它的 `persona.known_biases` 会包含对**具名真实人物**的
   准确度评价（例如"在某标的上命中率显著差于随机，却仍在推荐"）。
   把这些放在公开仓库上不合适。

所以公开仓库只放**引擎 + 合成样例**。真实数据请在本地生成、本地备份。

## 知识库长什么样

```
xxx.stkb（就是个 zip）
├── manifest.json       版本、来源、内容策略、各文件 sha256、支持的回测周期
├── author.json         ★ 作者画像 + persona（决策框架）—— 最有价值的部分
├── instruments.jsonl   自包含标的字典（App 不需要内置全市场代码表）
├── opinions.jsonl      结构化观点（方向、强度、周期、原话证据、事后回测）
├── evaluations.jsonl   回测明细（可无）
└── documents.jsonl     原文（仅 full_text 策略）
```

### `author.json` 的两层，别混淆

| 层 | 回答的问题 | 用来干什么 |
|---|---|---|
| `summary` / `methodology` / `known_biases` | **他是谁** | **描述**他（命中率、风格、偏见） |
| `persona` | **遇到没见过的新情况他会怎么想** | **扮演**他（规则、否决、清单、口头禅） |

`persona` 里最重要的字段是 `frameworks` —— **有名字的方法论**：

```
✗ 「他看多过某资源品、某赛道」   ← 流水账，遇到新标的就没用了
✓ 「政策管制会人为扭曲供需，
    被管制的资源品是最大催化剂」  ← 可迁移的规则，任何新管制品种都能套
```

合成库里的示例：

```json
{
  "name": "现金牛筛选法",
  "content": "只买自由现金流持续为正、且分红率稳定的公司。",
  "how_to_apply": "看近三年经营现金流净额是否为正、分红是否连续；若现金流靠应收账款堆出来，判定为伪现金牛。",
  "durability": "会计手法会变，现金流不会凭空产生。"
}
```

**`durability` 这一栏是关键**：具体结论会过期，方法不会。

## 三种用法

| 模式 | 输入 | 输出 | 性质 |
|---|---|---|---|
| 研究历史 | "他怎么看 X" | 历史观点 + 事后真实超额 | 只谈过去 |
| **请教军师** | "X 这个新情况" | 用他的框架推演 | 可迁移，不预测收益 |
| **检验我的操作** | "我 7/20 加仓了" | 逐条审你的单子 | **最诚实** |

**检验模式**的实测输出形态（真人那次的结果，标的已脱敏）：

```
| 你的操作              | 用他的框架怎么检验                                  |
|----------------------|---------------------------------------------------|
| 7/20 跌到 0.8471 加仓  | 破位二分法 → 前提是低位；0.8471 是历史什么位置？必须查证   |
| 8/5 卖了 1/3          | 除非卖的是纯概念股，否则是框架里的典型错误动作          |
| 某资源板块在你的持仓里   | 持有符合框架 —— 但你卖的那 1/3 是不是它？直接冲突        |
| 某主动基金             | 主动基金是框架里最别扭的工具，工具不合格                |
```

有价值的不是它判了"对/错"，而是它会**指出用户没问到的矛盾**，
并且**拒绝在没有数据时下结论**。

### 在 App 里用

1. 装 APK → **知识库页 → 载入** `demo_junshi_persona.stkb`
2. 载入后点「详情」可以看到完整决策框架（方法论 / 否决 / 清单 / 口头禅）
3. **会话页 → ＋ 新建**，选模式（有军师时默认「检验我的操作」）
4. 检验模式下直接在对话里贴操作，一行一条

> App 里**先查证再判断**是自动的：打包后走原生 HTTP，行情、公告、免密搜索都能用。
> 提示词会根据「当前工具是否可用」切换口径，不会让模型硬编数字。

### 命令行里用

```powershell
python run.py audit --author <名字> `
  --operations "7/20 跌到0.8471加仓`n8/5卖了1/3" `
  --context "持仓含某资源板块和某主动基金"
```

## 语料从哪来（采集策略）

不同来源对「决策框架」的价值差别很大：

| 来源 | 形态 | 价值 |
|---|---|---|
| 短帖 / 微博式发言 | 片段 | 低。**结论多、推理少**，只能提炼出"他看多过什么" |
| **长视频 / 直播回放** | 长时段口述 + 实时问答 | **最高**。他会把完整推理链讲出来，还会现场回答"某个新情况怎么办"——这正是 `persona` 最缺的素材 |
| 社群互动 | 实时表态 | 中 |

**如果能拿到音视频，优先拿。** 需要一个 ASR 环节把音频转成文本，
再走同一套 `import` → `extract` 流程。

**跨平台身份要合并**：同一个人在不同平台可能用不同名字，粉丝也会用别名称呼他。
用 `author-alias` 记录后，各家语料归到同一个军师：

```powershell
python run.py author-alias --author <主名> --add "某平台=某别名" --note "说明"
python run.py author-alias --author <主名> --set-note "其他平台无关的事实"
```

## 重新生成

```powershell
cd D:\dsh-stockTool

# 1) 提炼画像 + 决策框架（这一层最花心思，提示词在 src/stocktool/extract/persona.py）
python run.py profile-author --author <名字>

# 2) 导出（**一次只能导一位**，多作者会被拦下）
python run.py kb-export out.stkb --author <名字> --policy evidence_only

# 3) 校验
python run.py kb-validate out.stkb
```

改了别名表之后**不需要重跑 LLM**：

```powershell
python run.py re-resolve      # 零 API 成本地重新解析标的归属
python run.py dedupe          # 重新标记重复发帖
python run.py evaluate --horizons 5 20 60 250
python run.py kb-export ...
```

## 三条被数据修正过的结论

1. **判定要对着实测基线，不是 50%**
   A 股中位数个股本来就跑输市值加权指数。实测随机选股在同一批日期上的
   命中率只有 **44%/45%/43%**（T+5/20/60）。拿 50% 当原假设会冤枉所有人。

2. **必须看长周期**
   实测存在「短周期与随机无异、一年期却显著强于随机」的类型。
   他们是左侧 + 长期持有型，只跑短周期会把人误判成没水平。
   **周期必须匹配风格。**

3. **重复发帖必须去重**
   有人在同一天把同一段话回复多人，实测重复率可达两成（同一观点最多重复七次）。
   不去重会让样本量虚高、Wilson 区间变窄、p 值假性显著。

三条都已做成默认行为，并被测试守着。
